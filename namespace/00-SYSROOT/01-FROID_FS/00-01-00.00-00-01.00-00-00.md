[FROID_FS] is the projection of [SYSROOT] that stores a namespace as a filesystem tree, and its body is a set of rules and two restrictions governing how that tree is laid out. The naming rules derive each directory from the identifier it stands at: a constraint-bearing segment ([NOD_CSTR]) directory without a [FOLIO] takes the name of the [ND_SGMNT] at its position in the [NODE_ID], one that does carry a FOLIO takes the segment followed by its tag, and a directory standing for a selector segment ([NOD_BIN]) is named FF — except that a non-trailing selector of a leaf node not shared with a non-leaf node takes its own value as its name instead, which is the second restriction's reason for existing. Other rules suppress directories that would carry nothing: a trailing zero segment and the trailing selector of an identifier take no directory at all, while a zero segment directory in series with the root must carry a copy of the root FOLIO's [FRD_BODY], a copy the first restriction requires never to differ from the original. Further rules state the identifier shape the projection stores — at least one [NOD_BLOK], with the first block built from the namespace root segment, the projection segment, any projection-defined segments and the [MODE] selector, and the second block being the projection's own root block. Because FROID_FS also catalogs the grammar, the [NODE], [FOLIO] and [MODE] catalogs are held beneath it, and [PRJCTION] points back here as the filesystem projection of the namespace root.
